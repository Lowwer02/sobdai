# Assessment Blueprint — กรมสรรพากร นักวิชาการสรรพากร V1

## นักวิชาการสรรพากร — กรมสรรพากร

**ภาคความรู้เฉพาะตำแหน่ง** | คะแนนเต็ม 200 คะแนน (จุดใช้งาน V1 = 2 ชุด) | 100 ข้อ/ชุด | 5 ชุด (uniform allocation)

> **Engine Version**: 1.0.0 | **Blueprint Version**: 3.0.0 | **Position ID**: `revenue-academic-officer` | **Document Allocation**: quantified-physical

> **ขอบเขต V1 — Document Allocation Only**: Blueprint นี้กำหนดเฉพาะสัดส่วนรายเอกสาร (Document allocation) รวม 100 ข้อ/ชุด จาก 9 เอกสารที่มีข้อสอบ Published อยู่จริงในคลัง TAX-TRO (TAX-TRO-2026-V10) — ชื่อเอกสารทั้ง 9 เป็น exact stored strings จากคลัง ห้าม normalize / เติม-ตัดช่องว่าง / เติม-ตัดจุดหลัง พ.ร.บ. / เปลี่ยนรูปอักษรไทย (โดยเฉพาะเอกสาร 2 ฉบับ «พ.ร.บ.ข้อมูลข่าวสารของราชการ พ.ศ. 2540» และ «พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562» ที่เก็บโดยไม่มีช่องว่างหลัง «พ.ร.บ.»)
>
> **สิ่งที่ V1 ไม่กำหนด (ตั้งใจไว้)**: ไม่มี Pattern Distribution Target (คลัง TAX-TRO มี `question_pattern` เป็น NULL ทุก 680 ข้อ — พฤติกรรม degraded/unavailable ของ Engine ยังทำงานไม่เปลี่ยน ไม่ Fatal), ไม่มี Difficulty/Blueprint Type distribution และไม่มี Document×LO matrix — LO เป็น set-wide distribution เท่านั้น Engine เลือก joint Document×LO allocation จาก supply จริงของคลังเอง
>
> **เป้าหมาย LO เชิงปริมาณของ V1 เป็น PRODUCT DECISION**: LO1 28 / LO2 22 / LO3 23 / LO4 27 รวม 100 ข้อ/ชุดพอดี (ดูตารางสัดส่วน LO ต่อ Set) มิใช่ค่าที่วัดจากคลัง TAX-TRO จริงโดยตรง และไม่คัดลอกสัดส่วนจาก Blueprint อื่น (OAG-PPA 40/30/15/15, OPSMOAC-PPA 35/30/20/15, OAG-PFA 27/29/27/17) — ความเป็นไปได้ร่วม (joint feasibility) กับความจุ Document×LO จริงของคลัง 680 ข้อพิสูจน์แล้วด้วย Engine จริงในชุดทดสอบ runtime ของ Blueprint นี้
>
> **DocumentCode**: คลัง TAX-TRO มี `document_code` ครบ 680/680 (100% — DOC-TAX-INTRO, DOC-TAX-PIT, DOC-TAX-CIT, DOC-TAX-VAT, DOC-TAX-SBT-STAMP, DOC-EXAM-RD-OFFICER-2567, DOC-EXAM-RD-EST-2569, DOC-ACT-OFFICIAL-INFO-2540, DOC-ACT-PDPA-2562) — เป็นหลักฐานการตรวจสอบ (audit evidence) เท่านั้น Blueprint นี้ไม่อ้าง DocumentCode ในสัญญาการจับคู่ การจับคู่ยังใช้ Document identity ตามชื่อเอกสารเดิมทั้งหมด (v3.0 name identity)
>
> **ขอบเขตการแยกตำแหน่ง (position isolation)**: Candidate Loader ของแพ็กเกจอ่านเฉพาะข้อสอบที่เชื่อมกับ Exam Set ของ TAX-TRO-2026-V10 เท่านั้น — ข้อสอบ -TAXSPO (อีกตำแหน่งหนึ่งของกรมสรรพากร 120 ข้อ ที่มีชื่อ Document ตรงกัน 3 เอกสาร) และข้อสอบ พ.ร.บ.ข้อมูลข่าวสารฯ อีก 40 ข้อที่ไม่ได้เชื่อมกับแพ็กเกจ จึงเข้า Candidate Pool ไม่ได้ตั้งแต่การโหลด ส่วนข้อสอบชุดจำลอง (mock Exam Set) 50 ข้อที่มี `document` เป็น NULL โดนกรอง document ปฏิเสธ จึงใช้เติมโควตาเอกสารทั้ง 9 ไม่ได้

## Distribution Rules — Tier System

### Tier Definitions

| Tier | Label | Range (ข้อ/ชุด ต่อ Document) | เกณฑ์การจัดระดับ |
|---|---|---|---|
| **Tier 1** | Core | 5–10 | ภาษีอากรและประมวลรัษฎากร — ความรู้เบื้องต้น ภาษีเงินได้บุคคลธรรมดา ภาษีเงินได้นิติบุคคล ภาษีมูลค่าเพิ่ม และภาษีธุรกิจเฉพาะ/อากรแสตมป์ (สัดส่วน 5/10/10/10/5) |
| **Tier 2** | Domain | 13–17 | ความรู้เกี่ยวกับกรมสรรพากร — ภารกิจ โครงสร้าง และระบบบริการดิจิทัลของกรม (สัดส่วน 15) |
| **Tier 3** | Supporting | 28–32 | เศรษฐกิจ สังคม และเทคโนโลยี — บริบทปัจจุบันของภาครัฐและการปรับตัว (สัดส่วน 30) |
| **Tier 4** | Supplementary | 7–8 | กฎหมายข้อมูลข่าวสารและข้อมูลส่วนบุคคล — พ.ร.บ.ข้อมูลข่าวสารฯ 2540 และ พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคลฯ 2562 (สัดส่วน 7/8) |

### Distribution Constraints

```
FOR each simulation_set:
  SUM(all documents) = 100

  FOR each document:
    count >= tier.min
    count <= tier.max

  SUM(tier_1) >= 40   (5 + 10 + 10 + 10 + 5 ตามสัดส่วนตั้งต้นของ V1)
  SUM(tier_4) <= 15   (Tier 4 รวม 7 + 8 = 15)

  Anchor Rule:
    V1 ไม่ใช้ Anchor bonus: +0 above tier.max
    max 1 anchor per set
```

## Question Pattern Layer

> **หมายเหตุ V1**: ตารางด้านล่างเป็นคลังคำศัพท์รูปแบบโจทย์ (vocabulary) ตามสถาปัตยกรรม Engine v3.0 เท่านั้น — **ไม่ใช่เป้าหมายเชิงปริมาณของ V1** V1 ไม่วางตาราง Pattern Distribution Target เพราะคลัง TAX-TRO มี `question_pattern` เป็น NULL ทุก 680 ข้อ พฤติกรรม degraded/unavailable ของ Engine ยังทำงานไม่เปลี่ยน ไม่มี question_pattern Fatal (blueprint_type เป็นแกนต่างหากจาก question_pattern และไม่เท่ากับ LO โดยอัตโนมัติ)

### Pattern Types

| Pattern | คำอธิบาย | ตัวอย่างโจทย์ | สัดส่วน (vocabulary อ้างอิง v3.0 — ไม่ใช่เป้าหมาย V1) |
|---|---|---|---|
| **Positive** | ถามสิ่งที่ถูกต้อง | "ข้อใดกล่าว **ถูกต้อง**" | 35–40% |
| **Negative** | ถามสิ่งที่ไม่ถูกต้อง | "ข้อใด **ไม่ใช่** หลักการ..." | 15–20% |
| **Best Answer** | ตัวเลือกถูกหลายข้อ เลือกดีที่สุด | "ข้อใด **เหมาะสมที่สุด**" | 10–15% |
| **Scenario** | สถานการณ์จำลอง + คำถาม | "นาย ก. เป็นเจ้าหน้าที่... ควรดำเนินการอย่างไร" | 15–20% |
| **Sequence** | ถามลำดับขั้นตอน | "ลำดับขั้นตอนที่ **ถูกต้อง** คือข้อใด" | 5–10% |
| **Matching Concept** | จับคู่/เชื่อมโยง | "ข้อใดจับคู่ระหว่าง มาตรา กับ เนื้อหา **ถูกต้อง**" | 5–10% |

## Duplicate Prevention Rules

| Level | ขอบเขต | กฎ | Enforcement |
|---|---|---|---|
| **L1** | ภายใน Set | Topic + Difficulty + Type เดียวกัน = ห้ามซ้ำ | Hard |
| **L2** | ภายใน Set | Section/มาตรา เดียวกัน ≤ 3 ข้อ/Set | Hard |
| **L3** | ข้าม Set | Topic + Difficulty + Type เดียวกัน ห้ามเกิน 5 Set | Soft |
| **L4** | ข้าม Set | Concept/ประเด็นหลักต้องไม่ซ้ำเกิน 50% | Soft |
| **L5** | ข้าม Set | Scenario ต้องมีบริบทต่างกัน | Soft |

### Similarity Metric

```
calculate_similarity(question_a, question_b):

  topic_sim    = 1.0 if same_topic    else 0.0   (weight: 0.40)
  section_sim  = 1.0 if same_section  else 0.0   (weight: 0.20)
  type_sim     = 1.0 if same_type     else 0.0   (weight: 0.15)
  diff_sim     = 1.0 if same_diff     else 0.0   (weight: 0.10)
  keyword_sim  = jaccard(keywords_a, keywords_b)  (weight: 0.15)

  total = weighted_sum(above)

  >= 0.85 → BLOCK
  >= 0.70 → WARN
  <  0.70 → PASS
```
