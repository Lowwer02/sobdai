# Assessment Blueprint — SPKS นักวิเคราะห์นโยบายและแผน V1

## นักวิเคราะห์นโยบายและแผน — สำนักงานปลัดกระทรวงเกษตรและสหกรณ์

**ภาคความรู้เฉพาะตำแหน่ง** | คะแนนเต็ม 500 คะแนน | 100 ข้อ/ชุด | 5 ชุด

> **Engine Version**: 1.0.0 | **Blueprint Version**: 3.0.0 | **Position ID**: `opsmoac-policy-plan-analyst` | **Document Allocation**: quantified-physical

> **ขอบเขต V1 — Document Allocation Only**: Blueprint นี้กำหนดเฉพาะสัดส่วนรายเอกสาร (Document allocation) รวม 100 ข้อ/ชุด จาก 21 เอกสารที่มีข้อสอบ Published อยู่จริงในคลัง SPKS (OPSMOAC-PPA-2026-V10) — ชื่อเอกสารทั้ง 21 เป็น exact stored strings จากคลัง ห้าม normalize / เติม-ตัดช่องว่าง / เปลี่ยนรูปอักขระไทย / เปลี่ยนการเขียน พ.ศ.
>
> **สิ่งที่ V1 ไม่กำหนด (ตั้งใจไว้)**: ไม่มี Pattern Distribution Target (คลัง SPKS มี `question_pattern` เป็น NULL ทุกข้อ — พฤติกรรม degraded/unavailable ของ Engine ยังทำงานไม่เปลี่ยน ไม่ Fatal), ไม่มี Difficulty/Blueprint Type distribution และไม่มี Document×LO matrix — LO เป็น set-wide distribution เท่านั้น Engine เลือก joint Document×LO allocation จาก supply จริงของคลังเอง
>
> **เป้าหมาย LO เชิงปริมาณของ V1 เป็น PRODUCT DECISION**: LO1 35 / LO2 30 / LO3 20 / LO4 15 รวม 100 ข้อ/ชุดพอดี (ดูตารางสัดส่วน LO ต่อ Set) มิใช่ค่าที่วัดจากคลัง SPKS จริง และไม่คัดลอกสัดส่วนจาก Blueprint อื่น ความเป็นไปได้เชิงคลังจริง (live-bank feasibility) ยังต้องพิสูจน์ด้วย Engine จริงในขั้น Preview QA
>
> **DocumentCode**: Blueprint นี้ไม่อ้าง DocumentCode — การจับคู่ยังใช้ Document identity ตามชื่อเอกสารเดิมทั้งหมด (คลังมี DocumentCode 760/840 และมีชื่อ code ชนกันที่ DOC-ACTPLAN-MOAC-2566-2570 — เป็น backlog ของ Document Identity V2 ไม่บล็อก Blueprint V1)

### Distribution Constraints

```
FOR each simulation_set:
  SUM(all documents) = 100

  FOR each document:
    count >= tier.min
    count <= tier.max

  SUM(tier_1) >= 53   (9 + 7 + 7 + 6 + 6 + 6 + 6 + 6 ตามสัดส่วนตั้งต้นของ V1)
  SUM(tier_4) <= 5    (Tier 4 รวม 1 ตามสัดส่วนต่ำสุดของ V1)

  Anchor Rule:
    V1 ไม่ใช้ Anchor bonus: +0 above tier.max
    max 1 anchor per set
```

## Question Pattern Layer

> **หมายเหตุ V1**: ตารางด้านล่างเป็นคลังคำศัพท์รูปแบบโจทย์ (vocabulary) ตามสถาปัตยกรรม Engine v3.0 เท่านั้น — **ไม่ใช่เป้าหมายเชิงปริมาณของ V1** V1 ไม่วางตาราง Pattern Distribution Target เพราะคลัง SPKS มี `question_pattern` เป็น NULL ทุกข้อ พฤติกรรม degraded/unavailable ของ Engine ยังทำงานไม่เปลี่ยน ไม่มี question_pattern Fatal (blueprint_type เป็นแกนต่างหากจาก question_pattern และไม่เท่ากับ LO โดยอัตโนมัติ)

### Pattern Types

| Pattern | คำอธิบาย | ตัวอย่างโจทย์ | สัดส่วน (vocabulary อ้างอิง v3.0 — ไม่ใช่เป้าหมาย V1) |
|---|---|---|---|
| **Positive** | ถามสิ่งที่ถูกต้อง | "ข้อใดกล่าว **ถูกต้อง**" | 35–40% |
| **Negative** | ถามสิ่งที่ไม่ถูกต้อง | "ข้อใด **ไม่ใช่** หลักการ..." | 15–20% |
| **Best Answer** | ตัวเลือกถูกหลายข้อ เลือกดีที่สุด | "ข้อใด **เหมาะสมที่สุด**" | 10–15% |
| **Scenario** | สถานการณ์จำลอง + คำถาม | "นาย ก. เป็นเจ้าหน้าที่... ควรดำเนินการอย่างไร" | 15–20% |
| **Sequence** | ถามลำดับขั้นตอน | "ลำดับขั้นตอนที่ **ถูกต้อง** คือข้อใด" | 5–10% |
| **Matching Concept** | จับคู่/เชื่อมโยง | "ข้อใดจับคู่ระหว่าง มาตรา กับ เนื้อหา **ถูกต้อง**" | 5–10% |

## Duplicate Prevention Rules

| Level | ขอบเขต | กฎ | Enforcement |
|---|---|---|---|
| **L1** | ภายใน Set | Topic + Difficulty + Type เดียวกัน = ห้ามซ้ำ | Hard |
| **L2** | ภายใน Set | Section/มาตรา เดียวกัน ≤ 3 ข้อ/Set | Hard |
| **L3** | ข้าม Set | Topic + Difficulty + Type เดียวกัน ห้ามเกิน 5 Set | Soft |
| **L4** | ข้าม Set | Concept/ประเด็นหลักต้องไม่ซ้ำเกิน 50% | Soft |
| **L5** | ข้าม Set | Scenario ต้องมีบริบทต่างกัน | Soft |

### Similarity Metric

```
calculate_similarity(question_a, question_b):

  topic_sim    = 1.0 if same_topic    else 0.0   (weight: 0.40)
  section_sim  = 1.0 if same_section  else 0.0   (weight: 0.20)
  type_sim     = 1.0 if same_type     else 0.0   (weight: 0.15)
  diff_sim     = 1.0 if same_diff     else 0.0   (weight: 0.10)
  keyword_sim  = jaccard(keywords_a, keywords_b)  (weight: 0.15)

  total = weighted_sum(above)

  >= 0.85 → BLOCK
  >= 0.70 → WARN
  <  0.70 → PASS
```
